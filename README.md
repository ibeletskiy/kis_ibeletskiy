### Задача № 4

Для быстрой проверки на загруженных тестах нужно запустить `./run.sh`.

Для компиляции `g++ -std=c++20 -Ofast -o comparator comparator.cpp`
Для запуска `./comparator -A "example_A" -B "example_B" ...`

Параметр `-p` отвечает за учитываемый процент.
Кроме того есть параметр `-t`, ограничивающий количество используемых тредов.

Для сравнения используется алгоритм LCS, но так как для сравнения файлов размером до 10мб он не подойдет по скорости, было принято решение сделать адаптивное разбиение, при котором подсчет одной пары будет выполняться меньше ~0.5 секунды на одном ядре. Для этого оба файла делятся на блоки, размер которых определяется максимальным из размеров сравниваемых файлов (если говорить детальнее, то размер большего файла делится на $10^4$, и округляется вверх. Это число и будет размером блока, так как при таком размере количество блоков не будет превышать $10^4$, что означает что при времени исполнения $O(n^2)$ мы успеем уложиться в полсекунды), внутри каждого блока, в свою очередь, считается хеш, и по блокам в последствии и выполняется LCS. Очевидно что чем больше размер наибольшей общей последовательности, тем более "похожи" файлы.

Для эффективности также каждая проверка пары исполняется на отдельном потоке, что позволяет кратно ускорить исполнение программы.

Кроме того была идея написать также дополнительный вариант сравнения в виде дополнительной проверки LCS внутри некоторой части блоков после подсчета на их хешах, чтобы уменьшить вероятность ошибки, но не уверен что успел это реализовать. В теории также можно было бы брать случайные подпоследовательности из меньшего файла и использовать их для проверки.
